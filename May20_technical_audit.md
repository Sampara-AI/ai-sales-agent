Date: 2026-05-20

1) Executive Summary

- The demo flow is stable as a live, end-to-end outbound + “reply handling” experience.
- Outbound emails are sent via Resend and are generated by Groq, grounded in the Knowledge Base (RAG) when OPENAI_API_KEY is present.
- Inbound “intelligent reply” during the demo can be done reliably via Option B: paste the client reply into the in-app inbox panel, which runs intent detection + KB-grounded drafting and can auto-send the response.
- Resend inbound receiving automation exists in code (email.received webhook), but operationally it may be blocked by Resend’s free-tier domain limits and/or DNS/MX changes; Option B avoids these constraints entirely.

2) Demo-Critical User Journeys

2.1 Knowledge Base (RAG) Upload

Goal: Upload product docs and index them so the model stays grounded.

- UI: /admin
- Endpoint: /api/admin/knowledge
- Supports multi-file upload.
- Code: app/admin/page.tsx, app/api/admin/knowledge/route.ts

Expected result:
- Knowledge chunks are stored and retrievable via match_knowledge_chunks RPC (pgvector).
- Outbound + inbound drafts cite only available knowledge context (no hallucination policy enforced in prompt).

2.2 CSV → Enrich → Draft → Auto-Send (Guided “Wow” Flow)

UI: /dashboard/hunting

Stages:
- Import: upload CSV and immediately see prospects.
- Enrich: domain intel enrichment per prospect.
- Process: one-click pipeline to enrich (if needed) → generate outreach → send via Resend.
- Inbox: paste a reply → analyze → optionally auto-send response.

Key code (single-page orchestration):
- app/dashboard/hunting/page.tsx
- app/dashboard/hunting/CampaignCsvImporter.tsx

API dependencies:
- /api/campaigns/[id]/import (CSV import robustness + schema mismatch tolerance)
- /api/prospects/[id]/enrich-domain (domain intel)
- /api/generate-outreach (Groq + RAG)
- /api/send-email (Resend send)
- /api/inbox/respond (Groq + RAG reply drafting)

2.3 “Live Reply” for Demo (Option B)

This avoids Gmail/Google Workspace integration and Resend receiving requirements.

UI location:
- /dashboard/hunting → stage=inbox → “Paste reply” panel (anchor #reply)

What it does:
- Calls /api/inbox/respond with the pasted reply body (plus subject/from/to).
- Produces:
  - intent classification (curiosity/pricing/meeting/etc.)
  - escalation flag
  - confidence score
  - KB-grounded drafted response (subject + body)
  - knowledge_refs for traceability
- If “Auto-send” is enabled (default), sends the drafted reply to the prospect email via /api/send-email with allow_replied=true for demo smoothness.

Code:
- app/dashboard/hunting/page.tsx (server action analyzeInboundReply)
- app/api/inbox/respond/route.ts
- app/api/send-email/route.ts

4) Outbound Email Sending (Resend)

Endpoint:
- POST /api/send-email

Behavior:
- Uses Resend API to send email (HTML + text).
- Tracks sent events into email_campaigns and updates prospect status and timestamps.
- Allows internal “run_now” sends in demo mode or with x-internal-secret.

Brand/CTA alignment:
- CTA footer link text/url now defaults from AI settings (cta_text/cta_url), not hardcoded.
- Signature fields can be driven by AI settings (sender_title/sender_company/credibility_line).

Reply-To support:
- If RESEND_REPLY_TO is set, it is added to outbound messages as reply_to.
- Code: app/api/send-email/route.ts

Important operational note:
- Reply-To helps route replies to a specific mailbox, but true inbound automation still depends on the email provider/receiving setup.

5) Grounding / RAG Behavior (No Nonsense Policy)

Outbound generation:
- Uses OpenAI embeddings (text-embedding-3-small) to query match_knowledge_chunks.
- Prompt rules force grounding:
  - “Use only facts from recent_activity and knowledge_context”
  - “If evidence is weak, ask 1 short clarifying question instead of guessing”
  - “No hype, no emojis, no exclamation points”
- Code: app/api/generate-outreach/route.ts

Inbound reply drafting:
- Uses OpenAI embeddings over the inbound reply content.
- Retrieves knowledge snippets and forces “use only snippets as factual basis”.
- Stores structured fields back to inbox_messages for “analytics style” visibility.
- Code: app/api/inbox/respond/route.ts

6) Current State of “LIVE” Inbound Automation

Implemented in code:
- Webhook route exists: POST /api/webhooks/resend
- Handles email.received by calling Resend receiving API to fetch body and then calls /api/inbox/respond and /api/send-email.
- Code: app/api/webhooks/resend/route.ts

Operational blockers (common):
- Resend free-tier domain limits can prevent setting up a dedicated receiving domain/subdomain.
- Enabling receiving often requires MX/DNS changes that can disrupt existing Google Workspace email routing.

Recommended for this demo:
- Use Option B (paste reply) for deterministic success and explain that Gmail/Workspace is not integrated yet.

9) Known Demo Risks + Fast Fixes

- If /api/inbox/respond errors “Missing OPENAI_API_KEY”:
  - Set OPENAI_API_KEY in Vercel and redeploy.
- If /api/generate-outreach errors “Missing GROQ_API_KEY”:
  - Set GROQ_API_KEY in Vercel and redeploy.
- If /api/send-email errors:
  - Confirm RESEND_API_KEY.
  - Confirm sender/from address is allowed by your verified Resend domain.
- If KB grounding feels weak:
  - Upload more product docs in /admin and re-run.
  - Lower temperature in /dashboard/settings.
